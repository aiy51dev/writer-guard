# 公众号发布安全台 · Writer Guard v1.29.3

给公众号小编用的合规工作台。写稿时拦红线，发文前给评分，被投诉有台账，发布后自动回填数据。

**四个痛点对应四个动作：**

| 你的问题 | 工具里怎么做 |
|---|---|
| 平台不给推荐 | 发布评分 + AI 治理，把「内容农场」信号压掉 |
| 触发侵权 | 素材台账 + 重复图预警 + 字体自查 + **品类专属词库** |
| 被平台删文 | 红线词实时拦截，在编辑器里当场标出来 |
| 手动录数据太累 | **后台数据自动抓取**，回填到复盘看板 |

---

## 一、安装（Windows + Chrome / Edge，约 3 分钟）

1. 地址栏输入 `chrome://extensions`（Edge 用 `edge://extensions`）
2. 右上角打开 **「开发者模式」**
3. 点 **「加载已解压的扩展程序」** → 选择 `writer-guard` 文件夹
4. 弹出欢迎页即成功

> 需要 Chrome 111+（用了 `world: "MAIN"` 注入，用于抓取后台接口数据）。

**升级**：改完文件回 `chrome://extensions` 点卡片上的刷新圆圈，不用卸载重装。

## 二、每天怎么用

### 1. 设定一次（只做一遍）

工作台 →「团队设置」→ 填操作人名字 → 勾选你的品类（办公 / 设计 / 开发）。

品类勾上之后，检测台会额外叠加该品类的专属红线。

### 2. 写稿

**推荐路径：工作台 →「编辑台」**，左边写 Markdown、右边实时看公众号排版，写完三种交付任选：

1. **复制排版**：富文本进剪贴板，粘到任何编辑器都带样式
2. **写入编辑器**：自动打开你已登录的公众号图文页，把排版好的正文和标题直接写进去（零配置）
3. **推送草稿箱**：官方接口直推草稿箱（需在「团队设置 → 公众号绑定」填 AppID / AppSecret）

也可以按老习惯：进 `mp.weixin.qq.com` 图文编辑页，右下角会出现「安全台」按钮，颜色随风险变：🟢 通过 / 🟡 有优化项 / 🔴 有必删内容；点开看详情：命中哪个词、在哪一句、为什么、怎么改。编辑台写好的稿子可点「送进检测台跑红线」直接送检。

### 3. 发文前 30 秒

工作台 →「检测台」→ 粘贴标题和正文 → 看三个数：**发布评分 / AI 度 / 红线命中**。

评分 < 80 或 AI 度 ≥ 40，先改再发。

### 4. 发布后抓数据

1. 打开公众号后台 →「内容分析 → 图文分析」→ 点一次查询或翻页
2. 保持这个标签页在前台
3. 工作台 →「数据复盘」→ 点 **「抓取当前标签页」**
4. 核对预览表，取消勾选不想写的行 → 点 **「写入复盘看板」**

新增的会新建记录，已有的会更新阅读/完读/在看数值。

### 5. 被投诉后 72 小时内

工作台 →「投诉看板」→ 登记（自动算 72 小时倒计时）→ 复制申诉模板 → 附上素材台账和原始录屏。

## 五、后台数据自动抓取

### 原理

公众号后台的数据是 XHR 异步加载的，抓 DOM 不可靠（表格经常换结构）。所以做法是：

1. **MAIN world 注入**（`content/net-hook.js`）hook 掉 `fetch` 和 `XMLHttpRequest`，把接口响应的原始 JSON 转发出来
2. **自适应提取**（`content/data-scrape.js`）在 JSON 树里递归找「同时含标题字段和阅读字段」的对象数组
3. **字段名模糊匹配**，接口改名也能吃住
4. **DOM 表格兜底**：接口没截到时，直接解析页面表格

### 能识别的字段名

| 数据 | 支持的字段名 |
|---|---|
| 标题 | title / appmsg_title / msg_title / article_title / name |
| 阅读 | read_num / readnum / read_count / int_page_read_count / total_read |
| 完读率 | finish_rate / complete_rate / finish_percent / progress |
| 在看 | like_num / likenum / old_like_num / praise_num |
| 分享 | share_num / share_count / forward_num |
| 涨粉 | add_fans / new_fans / increase_fans |
| 日期 | date / stat_date / publish_date / sent_time（时间戳自动转换） |

数值类型也做了归一：`"0.42"` → 42%，`"860"` → 860，`1730419200` → `2024-11-01`。

### 抓不到怎么办

按顺序排查：

1. **是不是在数据页**——抓取需要当前标签页是 `mp.weixin.qq.com` 下的数据页面
2. **有没有触发过加载**——先点一次「查询」或翻页，接口才会发请求
3. **缓存是不是空的**——点「清空抓取缓存」，回数据页重新点一次查询
4. **接口完全没匹配上**——说明公众号换了路径特征。改 `content/net-hook.js` 里的 `PATH_HINT` 正则，把你 F12 看到的接口路径加进去
5. **字段没识别出来**——改 `content/data-scrape.js` 里的 `FIELDS` 映射表

抓不到也不影响用——「录入一篇的复盘数据」手动填一直是可用的。

## 六、封面设计器

### 为什么不用 AI 直接画字

原工具的标题是写进提示词让模型画的。AI 画中文几乎必出错字——笔画缺失、生造字、字母混进中文里。封面上出现错字，比没有封面更伤专业度。

所以这里的分工是：

- **AI 只画底图**：用「AI 底图」面板生成提示词，复制到任意绘图工具（即梦 / 豆包 / MJ / SD）
- **文字全部本地排版**：字体、字号、行高、字距、描边、阴影都由你精确控制

提示词里已经明确写了「不要出现任何文字」，负向词也带了「文字、字幕、标语、招牌文字、乱码」。

### 布局与折叠

左右两侧各有一条 **15px 的三角按钮栏**，默认两侧都收起，画布占满整个区域。

| 位置 | 内容 | 展开宽度 | 默认 |
|---|---|---|---|
| **左侧** | 工具面板：版式 / 尺寸 / AI 底图 | 252px | **展开** |
| **右侧** | 属性面板：画布背景 → 图层 → 位置与尺寸 → 排版特效 | 278px | 收起 |

左三角开合左边的工具面板，右三角开合右边的属性面板。

**图层列表在右侧属性面板里，紧跟在「画布背景」下面**——从上到下是「画布背景 → 图层 → 选中图层的属性」，一路顺着改，不用左右来回看。

加图层的按钮（文字/图片/矩形/圆形/线条）也跟着放在图层区块顶部。


点三角展开，再点收起。两侧可以同时展开，画布会自动重新计算缩放比例（适应窗口）。

## 在公众号页面内直接使用

装好扩展后打开 `mp.weixin.qq.com`，页面右下角有**两个悬浮按钮**：

| 按钮 | 颜色 | 作用 |
|---|---|---|
| 安全台 | 蓝 | 打开红线检测面板（右侧滑出） |
| 封面 | 紫 | **在页面内全屏打开封面设计器，不跳标签页** |

封面覆盖层按 `Esc` 或点右上角「关闭」退出。数据走同一个 `chrome.storage`，和独立标签页打开的工作台完全互通——在里面做的封面，回工作台的素材台账能看到记录。

这就是「绑定」的意思：不用离开公众号编辑页，写完稿顺手就能出封面。

### 图层系统

五种图层：**文字 / 图片 / 矩形 / 圆形 / 线条**。矩形和圆形可互相切换。

- 拖动移动，四角控制点缩放（文字层会等比改字号）
- 顶部控制点旋转，接近 90° 倍数会自动对齐
- 图层列表拖动排序即层级，双击改名
- 每层可单独锁定、隐藏
- 方向键微调 1px，Shift + 方向键 10px

### 图片的两种形态（别搞混）

工具栏和左栏各有一个加图入口，出来的东西完全不同：

| 入口 | 出来什么 | 用途 |
|---|---|---|
| 左栏「+ 图片」 | **图片图层**：按原图比例，画布 45% 宽，居中，**可拖动可缩放**，插在当前选中层之上 | 往封面里放产品图、截图、图标 |
| 工具栏「上传底图」 | **背景图**：铺满画布、只有一张、放最底层、**不参与吸附** | 给整张封面垫底 |

背景图在图层列表里显示为「背景图」带 ▦ 图标。重复上传背景会**替换**旧的，不会叠成好几层。

双击画布上的图片图层可以直接换图，属性面板里也能改「填满裁剪 / 完整显示 / 拉伸」和圆角。

### 文字排版

字号、字重（300–900）、行高、字距、左中右对齐、颜色、描边、阴影、背景块（圆角+内边距）。

**双击画布上的文字直接进编辑**。

### 画布背景：三种模式

背景设置**固定显示在属性面板顶部**，不管有没有选中图层都能改。

| 模式 | 说明 |
|---|---|
| 纯色 | 单一底色 |
| 双色 | 线性渐变，可调角度 |
| **四角**（默认） | 四个角各一色，双线性插值融合 |

### 四角渐变

这是真正的四角插值，不是四色扇区——左上、右上、右下、左下各一个颜色，中间自动平滑过渡。

CSS 的 `linear-gradient` 只能两色，`conic-gradient` 是扇形放射，都做不出这个效果。实现是用 **canvas 双线性插值**：先在 64×N 的低分辨率画布上逐像素算四角插值，再用 `imageSmoothingQuality: 'high'` 放大到目标尺寸。这样既准确又快（每次改色只算 64×24 个像素）。导出时用同一套算法，屏幕和成图完全一致。

**四角热区半径 56px**：圆点本身只有 18px，鼠标稍偏就会落到画布上、误触发画布缩放。所以滚轮判断用的是「离哪个角最近且距离 < 56px」，不是「有没有命中圆点」。这样在角上随手滚都在换色，画布不会被放大缩小。

**四角独立控制**：

- 画布四角各有一个小圆点（hover 才显现）
- 滚该角的圆点 → 只改这个角的颜色
- 点该角的圆点 → 取色器自定义

**不会撞色**：滚轮换色时会跳过另外三个角已经占用的颜色，整个色板被占满时才允许重复。测试里连续滚动 30 轮，每一步都校验四色互不相同。

属性面板里也有 2×2 的四角取色器（左上/右上 在上排，左下/右下 在下排），布局和画布位置对应。
### 一键插入公众号正文

封面设计器工具栏上有「**插入编辑器**」按钮，点一下就把当前画布生成图片塞进公众号正文。

**三档降级**，哪档能成就走哪档：

| 档 | 做法 | 说明 |
|---|---|---|
| ① | 构造 `paste` 事件 | 最接近真人粘贴，微信编辑器会自己走上传 |
| ② | `execCommand('insertImage')` | 先把光标折到正文末尾，再插图 |
| ③ | 写进剪贴板 | 提示「按 Ctrl+V 粘贴」，最稳的兜底 |

每档都会检查编辑器里 `img` 数量有没有真的变多，没变才降级。第 ③ 档加了 2 秒超时——没有用户手势时 `clipboard.write` 会一直挂着，不加超时整个流程就卡死。

**两种打开方式**：

- 在公众号页面里点「封面」FAB → 设计器是 iframe → 用 `postMessage` 把 PNG 的 ArrayBuffer 发给父页面，父页面直接插
- 在工作台标签页里打开 → 没有父页面，只能复制到剪贴板

所以想一键插入，请在**公众号编辑页**里打开封面设计器。
### 文件夹素材（20 个）

左侧「素材」页签里有 20 个文件夹样式的矢量素材，点一下插进画布，插入后就是普通图片图层——能拖、能缩放、能导出。

| 类型 | 素材 |
|---|---|
| 常用图标 | 文档 / 压缩包 / 图片 / 视频 / 音频 / 表格 / PDF / 代码 |
| 状态 | 加密（锁）/ 收藏（星）/ 云端（云）/ 设置（齿轮） |
| 配色 | 黄 / 蓝 / 紫 / 绿 / 粉 五色文件夹 |
| 带文字 | 下载 / 资料 / 模板 |

**带文字的三个支持修改**：插入时会生成**两个图层**——文件夹图（不含字）+ 一个文字层。文字层就是普通文字部件，双击画布上的字直接改，字号颜色位置都能调。

实现上是 Canvas 矢量绘制（512×512），不是位图切图。所以放大不糊，导出也是清晰的。

带字素材在面板里显示带字预览（方便辨认），插入画布时用的是无字版本 + 文字层，这样字才能改。
### 双击画布直接改字

**双击画布上的文字**，原地出现输入框，直接改，不用去右边面板找。

| 操作 | 效果 |
|---|---|
| 双击文字 | 原地出输入框，内容全选 |
| 直接打字 | 正常输入，框会跟着长高 |
| **Enter** | 换行（文字支持多行） |
| **Ctrl / ⌘ + Enter** | 提交 |
| **点别处** | 提交 |
| **Esc** | 取消，一个字都不改 |

细节：

- 输入框字体、字号、字重、行高、字距、对齐**都跟图层一致**，改的时候看到的就是最终效果
- 提交后自动重绘画布、刷新属性面板、触发自动保存
- **文字一变，逐字着色会清空**——因为字符索引对不上了，留着会串色
- 锁定的图层双击不会进入编辑
- 图片图层双击是「更换图片」，形状图层双击是选中

选中文字时，底部状态栏会显示「双击可直接改字」。
### 自动保存：改动即落盘，刷新不丢

画布上的**每一次改动都会自动存**，关掉页面、刷新、切走再回来，接着上次的继续。

工具栏右上角有状态指示：

| 显示 | 含义 |
|---|---|
| 保存中… | 正在写盘（灰） |
| 已保存 | 存好了（绿） |
| 已保存（图片过大未存） | 图层和排版存了，图片数据超配额被丢弃（橙） |
| 已恢复上次编辑 | 打开时从存档恢复（绿） |
| 保存失败 | 写盘出错（红） |

存的内容：画布尺寸、背景（三种模式 + 四色）、所有图层（位置/大小/文字/字号/颜色/逐字色/描边/阴影）、缩放、选中项。

**防抖 500ms**：连续拖拽只落盘一次，不会把存储写爆。

**图片配额兜底**：图片以 dataURL 存在图层里，撑爆 chrome.storage 配额时自动降级成「不含图片」的版本再存一次，布局不丢，只是图片需要重新上传。

**打开时的行为**：有存档就恢复存档，没有才铺默认画布（一个占位标题）。

想重来怎么办：挑一个新模板点击就会覆盖当前画布，自动保存会跟着更新。

### 交互实现说明（踩过的坑）

画布上的图层 DOM 在每次重渲染时都会重建，所以**事件监听必须用委托挂在不被重建的 canvas 上**，不能逐个绑到图层元素上。早期版本用了「只绑一次」的守卫标记，结果监听绑在了已经被替换掉的旧元素上，表现就是「画布完全不能拖」。

现在 `bindStageEvents` 采用事件委托，命中优先级为：

```
控制点 > 图层本体 > 空白
```

这个坑已经用 9 项真实 PointerEvent 测试锁住，任何一次重构把绑定改回去都会立刻失败。

## 七、团队协作

### 为什么不做实时同步

扩展没有后端服务器。做真实时同步要部署服务、搭账号体系、处理冲突——那是另一个项目。对 3–10 人的小编团队，**CSV 台账互换**更实用：零成本、可审计、出问题能回滚。

### 流程

```
A 采集             B 导出              C 合并              D 回发
各自本地登记    →   每人导出 CSV   →   管理员依次导入   →   合并后的 CSV
名字写进操作人      发到群里           选「合并」          发回群里各自导入
```

### 合并规则

- 按记录 `id` 去重
- 同一条记录，谁的 `updatedAt`（更新时间）更晚，就保留谁的版本
- 所以：**改完一条记录要重新保存一次**，否则时间戳没更新，合并不上

### CSV 结构

第一列 `_module` 标记这是哪张台账（素材台账 / 软件选题库 / 投诉看板 / 数据复盘），后面是统一列名。枚举值导出成中文（`自截自录`、`侵权`、`已申诉`），导入时自动还原成代码——这样可以在 Excel/飞书里直接看懂和编辑。

### 变更日志

「团队设置」里有完整日志：谁、什么时候、新增或删除了哪条记录。合并前先看一眼，能避开大多数冲突。

## 七点五、快速修改：一键降 AI 味

检测只是第一步。这一版加了**改写引擎**，两个入口：

| 入口 | 位置 | 行为 |
|---|---|---|
| 工作台 | 检测台「一键降 AI 味」 | 改写输入框内容，列出逐条修改，可「恢复原文」 |
| 公众号编辑器 | 注入面板底部「降 AI 味」 | **直接写回编辑器**，按钮变「撤销降味」 |

### 它改什么

五类规则，全部是「高置信度、不会改坏语义」的替换：

| 类别 | 例子 |
|---|---|
| 删除套话 | 首先，/ 其次，/ 值得一提的是，/ 众所周知，/ 在这个…时代，/ 随着…的发展， |
| 套话改写 | 综上所述 → 说白了 / 由此可见 → 所以 / 此外 → 另外 / 以下是三点 → 三条 |
| 黑话换白话 | 赋能→帮 / 闭环→完整流程 / 抓手→切入点 / 颗粒度→细致程度 / 底层逻辑→根本原因 / 降本增效→省钱省时间 |
| 修饰词收紧 | 非常强大 → 挺强大 / 极大地提升 → 大幅提升 / 令人惊叹 → 让人印象深刻 |
| 空白清理 | 多余空格、重复标点、行首空格、连续空行 |

### 实测效果

一段典型 AI 腔（首先其次再次 + 闭环赋能 + 底层逻辑颗粒度 + 众所周知）：

```
改写前：AI 度 高，发布评分 22 分（存在阻断项，不要发）
改写后：AI 度 15，发布评分 73 分（可以发，有优化项）
        158 字 → 126 字，共改 16 处
```

### 三条局限（必须知道）

1. **只动词，不改句子结构**。规则硬拆句子只会更别扭，句式重构该交给模型。
2. **句长均匀度改不了**。AI 度里的「句长σ」这一项属于结构问题，要手动插短句。
3. **缺真实细节改不了**。版本号、报错原文、翻车记录这些必须你自己加。

规则改完还是要通读一遍。

### 组合词的处理（踩过的坑）

「形成了完整闭环」如果先被通用规则 `闭环 → 完整流程` 命中，会变成「形成了完整**完整**流程」。

所以词表顺序有硬约束：**长串组合词必须排在同词根短规则之前**。现在 `形成了完整闭环`、`完整闭环`、`实现降本增效`、`底层逻辑清晰`、`颗粒度细` 这些组合规则都在前面，且有专门的回归测试守着。

### 流程

1. 选平台 → 自动带出接口地址和模型名
2. 粘贴 Key → 点「**验证并保存**」
3. 验证通过 → 表单收起，变成一行：绿点 + 平台名 + 模型 + **Writer Guard** 徽章
4. 侧边栏「封面设计」右侧亮起**绿点**（呼吸动画）

### 验证是怎么做的

先打 `GET /models`（免费、快）。返回 401/403 直接判定 Key 无效；接口不支持 `/models`（404）就退回一次 `max_tokens: 1` 的 chat 请求探活。

### 存储与刷新

存在 `chrome.storage.local` 的 `wg_aiConfig` 里，**刷新不丢**。字段：`provider / key / baseUrl / model / verified / lastCheck / lastMsg`。

### 24 小时静默复验

`chrome.alarms` 注册一个 24 小时周期的任务（`background.js`），到期后打一次验证接口：

- 有效 → 只更新 `lastCheck`
- 失效 → 把 `verified` 改成 `false`
- **全程不弹通知、不动角标**，下次打开设置页才看到「验证已失效」

设置页打开时也会调一次 `silentRecheck()`，但不到 24 小时不会真的发请求。

### 安全说明

Key 只存在本机浏览器存储里，不上传任何第三方服务器。验证请求直连你选的那家平台。
## 七点五三、手动检测模式

**不自动扫描。** 只有你点面板底部的「开始检测」，才会去读正文、跑一遍红线 + AI 痕迹。

这样做的原因：公众号编辑页是个持续变化的 DOM，自动监听要么漏（只等 30 秒）、要么一直占资源（MutationObserver + 轮询）。改成手动后：

- 没有 MutationObserver、没有 setInterval、没有 input 监听
- 打开面板不扫描，只回显上一次的结果；没检测过就显示「未检测」
- 你在编辑器里改内容，检测结果**保持不变**，不会自己重扫
- 想更新就再点一次「开始检测」

面板状态：

| 显示 | 含义 |
|---|---|
| 未检测 | 还没点过检测按钮 |
| 分数 + 标签 | 检测完成，显示上次结果 |
| 没找到正文编辑区 | 点了检测但没定位到编辑器，会告诉你怎么办 |
## 七点五四、面板一直显示「等待检测」怎么查

这个状态说明面板已经注入了，但**没找到正文编辑区**，或者扫描过程崩了。这一版修了两个原因：

### 原因一：只等 30 秒就放弃

旧代码每 500ms 找一个编辑器，找 60 次（30 秒）还没找到就彻底放弃，之后再也不会重试。公众号的编辑区是动态生成的——先开草稿箱、再点「新建图文」，编辑区出来时早就过了 30 秒。

现在改成三路兜底，**永不放弃**：

1. 编辑器一建好就挂上（`MutationObserver` 盯 DOM 变化）
2. 每 2 秒低频轮询一次，编辑器被替换了也能重新挂
3. 手动点「重新检测」，立即重新查找

### 原因二：词库格式改了，这里的扫描器没跟上

`content.js` 里有自己的一份 `scanRedline`（公众号页面不加载工作台的 engine.js）。上一版把词库的 `patterns` 从裸正则改成了 `{ re, to }` 带替换词，工作台的引擎改了，**这里没改**。

结果：拿到对象当成正则用，`re.source` 是 undefined，`new RegExp(undefined, ...)` 直接抛错。整条 `buildReport → render` 链断掉，verdict 永远停在初始文案。

现在两处都兼容两种格式，顺带把「替换词」也带进了面板。

### 现在的查找顺序

1. 已知选择器（`.ProseMirror` / `#js_editor` / `.edui-body-container` …）
2. 页面上任何 `[contenteditable]`，取文字最多的可见的那个
3. 同源 iframe 里找

三层都找不到，点「重新检测」会明确告诉你「没找到正文编辑区」，而不是干等着。

**还找不到的话**：把公众号编辑页的地址发我，我加对应规则。

| 按钮点了完全没动静，也没有提示 | 页面上的还是旧版 content script | 重载扩展 + 强刷页面 |

### 这一版修的一个真 bug

公众号编辑器会**动态重建 DOM**。原来代码里缓存了 `state.editor`，编辑区重建后这个引用就失效了——元素已经不在文档里，`focus()` 打不上去，`execCommand` 也就无从下手，改写静默失败，界面毫无反馈。

现在改成每次操作前先验证：

```js
function getLiveEditor() {
  const cached = state.editor;
  if (cached && document.contains(cached) && cached.isContentEditable) return cached;
  const fresh = findEditor();   // 失效就重新找
  if (fresh) state.editor = fresh;
  return fresh;
}
```

配合「按钮自检 + 红色错误提示」，以后点下去没反应的概率很低；万一失败，面板上会明说是什么原因。

## 八、去 AI 审核

平台识别 AI 内容不是看单一特征，而是几个信号叠加打分。所以正解不是伪装，是**把 AI 生成比例压下去，把真实经验密度提上来**。这在平台规则内是允许且被鼓励的。

### 平台实际在看的五个信号

1. **连接词密度** — 首先 / 其次 / 此外 / 综上所述 / 由此可见
2. **句式均匀度** — 句长方差小，每句长度差不多
3. **黑话密度** — 赋能 / 闭环 / 抓手 / 颗粒度 / 底层逻辑
4. **段落长度方差** — 每段长度高度一致
5. **有没有不可伪造的真实经验** — 具体型号、版本号、报错原文、失败记录

工具里的「AI 度」按这五项算出来，0–100 分，**低于 40 才算安全**。

> 判定逻辑有一处细节值得说：真人写短句流时句长方差也很小，但那是风格不是机器味。所以工具只在「平均句长 ≥ 18 字且长度趋同」时才判 AI，避免误伤。

### 七个手法（按效果排序）

**1. 删掉所有连接词**
首先、其次、再次、最后、此外、综上所述、由此可见、值得一提的是——这些是 AI 的骨架。删完之后段落靠事实自然衔接，机器味立刻掉一半。

**2. 刻意打乱句长**
插一句 5 字以内的短句，再写一句 40 字以上的长句。

> ❌ 该软件具有强大的功能和极致的用户体验，能够显著提升工作效率。
> ✅ 启动 1.2 秒，导出一张 4K 图 3 秒。但设置项藏在三级菜单里，我找了十分钟。

**3. 塞进不可伪造的具体细节**
设备型号、软件版本号、具体日期、第几步出错、错误提示原文。AI 编不出真实的报错信息。

**4. 写失败和翻车**

> 我试了 6 个工具，5 个在第三页就开始乱码。

真实经验一定包含失败。AI 只写成功路径。

**5. 换掉黑话**
赋能、闭环、抓手、粒度——换成具体动作。

> ❌ 它可以帮助你实现降本增效，形成业务闭环。
> ✅ 原来两个人做一天的活儿，现在一个人两小时。

**6. 段落长度不要均匀**
一段 2 行，下一段 8 行，再一段 1 行。

**7. 加口语和自嘲**

> UI 丑得我差点卸载。但它现在是常驻工具。

AI 不会自嘲。

### 合规边界（这条别踩）

2025 年 9 月起施行的《人工智能生成合成内容标识办法》要求：AI 生成的内容需按规定标注。

务实做法：**测试、截图、结论、踩坑全部自己完成，AI 只用于资料整理和排版。** 这样既不用强制标注，也不会有 AI 味。

如果稿子确实是 AI 主写的，如实加一句辅助说明，比被平台识别出来的后果轻得多：

> 本文测试与结论由本人完成，写作过程中使用了 AI 工具辅助整理，全部内容经本人核实。

## 九、常见问题

**Q：编辑器里没出现「安全台」按钮？**
微信编辑器会改 DOM 结构。打开 `content/content.js`，把新的选择器加进 `EDITOR_SELECTORS` 数组（按 F12 找编辑区的 class 或 id），刷新扩展即可。

**Q：点「抓取当前标签页」提示不是公众号页面？**
抓取功能要求当前活动标签页是 `mp.weixin.qq.com`。先点「打开图文分析页」，在那个页面上操作。

**Q：数据会传到哪？**
不传任何地方。全部存在本机浏览器的 `chrome.storage.local`。换电脑前用「团队设置 → 导出 JSON 备份」。

**Q：多台电脑怎么同步？**
导出 JSON 备份 → 另一台「合并导入 JSON」。同一账号也可以用 Chrome 自带的扩展数据同步，但多人协作请走 CSV 流程。

**Q：想先看看界面不想装？**
直接双击 `workbench/workbench.html`，大部分功能能跑（数据存 localStorage）。抓取和编辑页拦截需要装扩展。

**Q：改了词库怎么生效？**
编辑 `data/dict.js` → 回扩展页点刷新圆圈。不用重新打包。

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-xs` | 12px | 徽章、辅助标签 |
| `--fs-sm` | 12.5px | 说明文字、表格头 |
| `--fs-base` | 13.5px | 正文、输入框、表格 |
| `--fs-md` | 14.5px | 卡片内小标题 |
| `--fs-lg` | 16px | 卡片标题 |
| `--fs-xl` | 19px | 页面标题 |

行高从 1.65 提到 1.72，加 `letter-spacing: .012em` 让中文不挤。

### 这一版修掉的两个渲染问题

**AI 进度条不显示**：原本用 `<i style="width:61%">` 做进度，实际渲染宽度恒为 0（父容器 460px 正常、`display:block`、无 `!important`，换成 div 和固定 px 都一样）。改用**容器渐变**实现，不依赖子元素宽度：

```js
bar.style.background = `linear-gradient(90deg, ${color} ${pct}%, #e7ebf2 ${pct}%)`;
```

**评分环数字偏上**：`align-items: baseline` + `line-height: 78px` 导致垂直不对齐，改成 `align-items: center` + `line-height: 1`，"分"字用 `align-self: flex-end` 贴底。
